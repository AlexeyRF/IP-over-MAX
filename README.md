# IP-over-MAX

Проект протокола для IoT-устройств, который использует мессенджер MAX в качестве транспортного уровня для обмена сообщениями в период ограничений сотовой связи. Клиент поднимает локальные UDP-порты для приема данных и пересылает их через MAX, обеспечивая шифрование, фрагментацию и гарантии доставки.

## Особенности

*   **Три режима передачи данных**:
    *   **PTCP (Pseudo-TCP)** — Гарантированная доставка. Клиент отправляет сообщение и проверяет историю чата. Если сообщение не появилось в истории, оно отправляется повторно (каждые 15 секунд).
    *   **PUDP (Pseudo-UDP)** — Отложенная отправка. Если соединения с сервером нет, клиент ждет его восстановления и только затем отправляет пакет.
    *   **UDP** — Отправка "выстрелил и забыл". Пакет улетает в MAX мгновенно (если нет соединения, пакет может быть потерян).


## Требования

*   Python 3.8+
*   Аккаунт в мессенджере MAX

```bash
pip install maxapi-python cryptography
```

## Использование

Запустите клиент:

```bash

```

### Примеры отправки данных (Python)

Клиент ожидает данные на портах 10001-10003 в формате `[UUID|]Сообщение`. Если `UUID|` не указан, сообщение считается широковещательным (`broadcast`).

#### 1. Широковещательное сообщение (Broadcast)
Отправляется всем участникам в открытом (но упакованном) виде.

```python
import socket
with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as s:
    # Формат по умолчанию - broadcast
    s.sendto(b"Hello everyone!", ("127.0.0.1", 10002)) # PUDP
```

#### 2. Личное сообщение (Targeted/Encrypted)
Если указан UUID, клиент автоматически зашифрует сообщение публичным ключом получателя.

```python
import socket
# UUID берется из логов клиента при получении сообщения от другого участника
target_uuid = "ZTI5Y2Y3YjYtYmU0Ny00ZDk1LWE4ZWUtYmY5MjNjYmU0ZGIw"
data = f"{target_uuid}|Secret message for you".encode()

with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as s:
    s.sendto(data, ("127.0.0.1", 10001)) # PTCP (с гарантией доставки)
```

## Автоматическая фрагментация

Клиент **автоматически** определяет тип сообщения (`content` или `content_part`):
*   Если зашифрованное сообщение помещается в **3000 символов**, оно отправляется одним пакетом с типом `content`.
*   Если сообщение длиннее, оно автоматически разбивается на части по 3000 символов. Каждая часть отправляется с типом `content_part`, порядковым номером (`part`) и общим количеством частей (`total_parts`).

Это позволяет обходить лимиты мессенджера и передавать большие объемы данных через текстовые сообщения.


## Формат протокола (IP-over-MAX-v1)

Все сообщения внутри MAX передаются в виде JSON-строк:

**Стартовое сообщение (обмен ключами):**
```json
{
  "protocol": "IP-over-MAX-v1",
  "type": "start",
  "author": "<base64_uuid>",
  "recipient": "broadcast",
  "pub_key": "<PEM_public_key>"
}
```

**Передача данных:**
```json
{
  "protocol": "IP-over-MAX-v1",
  "type": "content",
  "author": "<base64_uuid>",
  "recipient": "broadcast", // или <base64_uuid> получателя
  "content": "<encrypted_and_base64_encoded_content>"
}
```
